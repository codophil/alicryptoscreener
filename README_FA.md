# راه‌اندازی کامل Altcoin Market Watcher V3

این پروژه یک پایشگر **Binance USD-M Perpetual Futures** با اجرای دوره‌ای GitHub Actions و ارسال پیام به بات تلگرام است. هیچ API Key از بایننس، اشتراک پولی یا سرور شخصی نمی‌خواهد. همه کدها با کتابخانه استاندارد Python اجرا می‌شوند.

**این نسخه پایش دائمیِ لحظه‌ای نیست.** GitHub حداقل هر ۵ دقیقه برنامه را زمان‌بندی می‌کند و ممکن است اجرای آن با تأخیر شروع شود یا بعضی نوبت‌ها اجرا نشوند. هشدارهای WHALE فقط از **نمونه آخرین ۱۰۰۰ معامله تجمیعی انجام‌شده** در حداکثر ۱۸ نماد پرحجم گرفته می‌شوند، نه همه سفارش‌های نهنگ‌ها؛ ممکن است معامله‌ای بین دو اجرا دیده نشود. برای پوشش واقعیِ لحظه‌ای نیاز به WebSocket و برنامه همیشه‌روشن است.

## فایل‌ها

```text
repo-root/
├── watcher.py
├── config.json
├── state.json
├── README_FA.md
├── tests/
│   └── test_watcher.py
└── .github/
    └── workflows/
        └── watcher.yml
```

## مهاجرت از پروژه قبلی، با حفظ بات تلگرام

1. وارد مخزن GitHub قبلی `altcoin-radar` شوید و به **Settings > Secrets and variables > Actions** بروید. مطمئن شوید این دو Secret هنوز هستند: `TELEGRAM_BOT_TOKEN` و `TELEGRAM_CHAT_ID`. **مقدارشان را تغییر ندهید و به هیچ‌کس ندهید.** این دو Secret با پاک‌کردن فایل‌های مخزن پاک نمی‌شوند.
2. در **Settings > Actions > General**، بخش **Workflow permissions** مقدار **Read and write permissions** را فعال و ذخیره کنید. اگر گزینه در مخزن شما غیرفعال یا قفل شده است، بخش `permissions: contents: write` فایل workflow هم باید اجازه نوشتن بگیرد؛ برای این کار محدودیت سازمان یا مخزن باید برطرف شود.
3. در تب **Code** پروژه، فایل‌های قدیمی `radar.py`، `state.json` (نسخه قدیمی)، و **فایل قدیمی** `.github/workflows/radar.yml` را حذف/جایگزین کنید. **ضروری:** اگر `radar.yml` باقی بماند، بات قدیمی نیز جداگانه اجرا می‌شود. می‌توانید README قبلی را هم حذف کنید. به هیچ‌وجه کل Repository را حذف نکنید؛ چون Secretها و تاریخچه آن از بین می‌روند.
4. فایل ZIP جدید را از حالت فشرده خارج کنید و فایل‌های آن را با **همان ساختار پوشه** در ریشه Repo قرار دهید. فایل `.github/workflows/watcher.yml` باید در مسیر مخفیِ `.github/workflows/` باشد، نه در ریشه.
5. آسان‌ترین روش برای کار با تعداد فایل: صفحه Code مخزن را باز کنید و کلید `.` (نقطه) را بزنید تا ویرایشگر وب `github.dev` باز شود. در Explorer فایل‌های قدیمی را حذف کنید؛ فایل‌های جدید و پوشه‌ها را کپی/ایجاد کنید؛ سپس در بخش Source Control تغییرات را Commit و Sync/Push کنید. اگر با این محیط آشنا نیستید، در GitHub معمولی با Add file > Upload files فایل‌های جدید را بارگذاری کنید و برای ساخت مسیر مخفی از Add file > Create new file با نام کامل `.github/workflows/watcher.yml` استفاده کنید. دقت کنید با آپلود فایل جدید، فایل‌های قدیمی خودبه‌خود حذف نمی‌شوند.
6. در تب **Actions**، از سمت چپ **Altcoin Market Watcher V3** را انتخاب کنید. **Run workflow** را بزنید و ابتدا `test_mode=true` را اجرا کنید. باید پیام تست تلگرام را دریافت کنید.
7. اجرای دستی دوم: `test_mode=false`. گزارش برنامه را در **Actions > اجرای جدید > scan > Scan and notify** بخوانید. اگر هیچ ارزی معیارها را نداشت، پیام تلگرام ارسال نمی‌شود و در گزارش `sent=0` دیده می‌شود.
8. پس از ذخیره workflow در شاخه پیش‌فرض مخزن (`main` یا شاخه پیش‌فرض واقعی شما)، اجراهای زمان‌بندی‌شده خودکار شروع می‌شوند. نیاز نیست کامپیوتر روشن بماند.

### پیغام‌هایی که ممکن است در Logs ببینید

- `Scanning 80 USD-M perpetual pairs`: شروع اسکن؛ اگر تعداد کمتر بود طبیعی است.
- `Pairs=... | active_volume=... | OI_calls=... | OI_missing=... | candidates=... | sent=...`: خلاصه هر اجرا.
- `All requested OI values unavailable`: دسترسی یا تازگی داده OI برای اسکن کافی نبوده؛ AWAKENING و EARLY BUY WATCH که نیازمند OI هستند ممکن است ارسال نشوند.
- `FATAL ... Binance`: اگر API فیوچرز از آی‌پی اجرای GitHub در دسترس نباشد، این پروژه بدون منبع داده جایگزین کار نمی‌کند؛ خطا در گزارش ثبت می‌شود و داده ساختگی نشان داده نمی‌شود.
- `Permission denied` یا `403` در مرحله `Persist alert state`: تنظیمات Workflow permissions و حفاظت شاخه `main` را بررسی کنید. اگر Push ممنوع باشد، محدودیت تکرار پیام‌ها بین اجراها پایدار نمی‌ماند.

## تنظیماتی که قابل تغییرند

در تب Code، فایل `config.json` را باز و دکمه مداد Edit را بزنید و Commit کنید.

| تنظیم | مقدار پیش‌فرض | کاربرد |
|---|---:|---|
| `max_symbols` | 80 | حداکثر ۸۰ نماد پرحجم Futures بررسی می‌شوند |
| `min_24h_quote_volume_usdt` | 10000000 | حداقل حجم دلاری در ۲۴ ساعت |
| `baseline_candles` | 30 | حجم هر کندل ۵دقیقه‌ای با میانگین **۳۰ کندل بسته قبلی** (۱۵۰ دقیقه)، نه میانگین ۳۰ دقیقه، مقایسه می‌شود |
| `max_alerts_per_run` | 8 | حداکثر ۸ هشدار برای هر اجرا |
| `awakening.min_relative_volume` | 5 | حداقل RVOL برای بیداری |
| `awakening.min_abs_oi_change_pct` | 1 | حداقل اندازه تغییر OI؛ مثبت یا منفی |
| `momentum.min_abs_price_move_pct` | 2 | حداقل قدر مطلق تغییر قیمت یک کندل پنج‌دقیقه‌ای |
| `early_buy_watch.min_buy_pressure_pct` | 58 | حداقل نسبت حجم تهاجمی خرید |
| `whale_trade.min_trade_usdt` | 1000000 | ارزش معامله تجمیعی بزرگ |
| `whale_trade.scan_top_symbols` | 18 | چند ارز پرحجم برای نمونه معاملات بزرگ بررسی شوند |

برای خاموش کردن هر نوع هشدار، مقدار `enabled` آن را `false` کنید.

## تعریف داده‌ها

- **AWAKENING:** جهش حجم ۵دقیقه‌ای در حالی که حرکت همان کندل هنوز خیلی بزرگ نشده و OI پنج‌دقیقه‌ای به‌قدر کافی تغییر کرده باشد. برای OI مثبت یا منفی هشدار می‌دهد.
- **MOMENTUM:** افزایش حجم و حرکت قیمتی قدرتمند رو به بالا **یا** پایین. حتی وقتی OI در دسترس نباشد قابل بررسی است.
- **EARLY BUY WATCH:** حجم نسبی زیاد، فشار Taker Buy زیاد، افزایش قراردادهای باز و رشد محدود قیمت.
- **LARGE AGGREGATED TRADE:** ترید اجراشده تجمیعی از `aggTrades`؛ ممکن است چند پرشدن سفارش در بازه زمانی کوتاه را نشان دهد. این **سفارش بازِ Order Book** نیست. فقط بخشی از معاملات اخیر بررسی می‌شوند.
- **Buy/Sell Pressure:** `taker buy quote volume ÷ total quote volume × 100` در کندل ۵دقیقه‌ای فیوچرز؛ این سهم معاملات تهاجمی خرید است، نه نسبت سفارش‌های معلق.
- **OI Change:** مقایسه دو نمونه متوالی `sumOpenInterest` با فاصله پنج دقیقه؛ تغییر تعداد قراردادهاست، نه ورود قطعی پول لانگ یا شورت. اگر نمونه تازه و سازگار نباشد `N/A` نمایش داده می‌شود.
- **Score /10:** امتیاز قانون‌محور برای فعالیت بازار؛ احتمال موفقیت یا جهت رشد نیست. هر موتور امتیازدهی خودش را دارد.
- **Move:** تغییر Open تا Close آخرین کندل **بسته‌شده پنج‌دقیقه‌ای**. این با `move` کانال نمونه ممکن است متفاوت باشد.

## محدودیت‌های عملی

- بیشتر خروجی‌های بازار از داده کندل **بسته‌شده** است تا حجم نیمه‌کاره فریبنده نباشد. هر زمان که GitHub کار را اجرا کند آخرین کندل کامل ارزیابی می‌شود.
- سیستم متکی به Futures Binance است؛ تحریم جغرافیایی یا محدودیت IP میزبان GitHub ممکن است باعث خطا شود. نتیجه را در Logs ببینید.
- اگر اجرای برنامه طول بکشد یا GitHub اجراها را بیندازد، ممکن است برخی حرکات و معاملات دیده نشوند. برای معاملات لحظه‌ای باید یک پردازش دائمی WebSocket ساخت.
- `state.json` فقط کلید هشدار و زمان را نگه می‌دارد، نه توکن تلگرام. اگر مخزن Public باشد این اطلاعات قابل دیدن هستند؛ توکن در GitHub Secrets محفوظ می‌ماند.
- هر پنج دقیقه در زمان‌های 02,07,... UTC زمان‌بندی شده؛ آغاز واقعی می‌تواند با تأخیر باشد.
- هیچ سفارش خرید/فروش از سوی این پروژه ارسال نمی‌شود.
